# 后端代码审查报告

> 项目：正隆记槟榔商城 backend（Spring Boot 3.5.6 / JDK 21 / JPA / H2）
> 审查时间：2026-10-23 ｜ 审查范围：125 个 Java 文件（common / framework / mall 三层）
> 方法：分层架构核对 + 静态扫描（事务注解、异常处理、日志、注入方式、魔法值、越层访问）+ 关键资金链路人工走读

## 一、总体结论

**整体符合规范，可进入联调阶段。** 架构分层清晰、事务边界正确、异常体系统一、无Bad Smell大面积堆积。本次审查发现 2 处问题（1 处分层违规、1 处异常信息外泄），均已当场修复并回归通过。

## 二、分层架构 ✅

| 层 | 组织 | 结论 |
|---|---|---|
| common | constant / core / exception / utils | 与参考工程（若依风格）一致 |
| framework | config / security / task / web | 横切关注点独立，未污染业务层 |
| mall | controller(api/admin) / service / repository / domain(dto) | 买卖端按 controller/api 与 controller/admin 分离 |

- 全部 125 个文件按包归位，无游离类。
- **发现 P2 问题**：`ProductController` 到货提醒接口直接注入 `ArrivalRemindRepository` 落库，绕过 Service 层。
  **已修复**：下沉为 `ProductService.saveArrivalRemind()`，并补充「商品在售无需登记」业务校验。

## 三、事务与一致性 ✅

- 下单 `OrderService.create`：`@Transactional`，订单落库与库存预占同事务，幂等键 5 分钟窗口 ✅
- 支付 `pay`、退款 `AfterSaleService.refund`（幂等）、发货、核销：均在事务内且带状态机校验 ✅
- 库存原子更新使用条件 UPDATE（available 不足即失败），无先读后写竞态 ✅
- 定时关单（15 分钟）关单前二次校验状态，防并发误关 ✅

## 四、异常与日志 ✅（修复 1 处）

- 全局异常处理器 `GlobalExceptionHandler`：业务异常返回 message、系统异常统一「系统繁忙」，HTTP 恒 200 由 code 区分 ✅
- 全库 0 处 `System.out.println`、0 处 `printStackTrace`、0 处空 catch、0 处 TODO ✅
- 日志统一 `@Slf4j`，构造注入统一 Lombok `@RequiredArgsConstructor`（0 处字段注入 `@Autowired`）✅
- **发现 P3 问题**：批量发货失败原因直接回传 `e.getMessage()`，非业务异常会把内部信息泄露给前端。
  **已修复**：区分 `ServiceException`（回传业务原因）与 `Exception`（记日志 + 统一话术）。

## 五、其余检查项

| 项 | 结果 |
|---|---|

| 金额口径 | ✅ 全链路整数分，无浮点计算；积分/抵现换算集中在 MemberService/OrderService |
