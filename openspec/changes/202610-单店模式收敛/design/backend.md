## Context

`DemoDataInitializer` 目前种入 3 家门店（正隆记总号/熙春路店/益阳领秀资江店），就绪日志写「门店 2 家」（旧文案缺陷）。Web 管理端门店页（views/store/index.vue）有「＋ 新增门店」按钮、门店编辑弹窗（新增/编辑共用）、核销表单门店下拉与「H5 端买家可切换门店」提示。H5 切换交互已在此前迭代移除。

## Goals / Non-Goals

**Goals:**

- 全链路单店语义一致：数据 1 家、管理端无新增入口、核销固定默认门店、文案无歧义。

**Non-Goals:**

- 不删除后端多店接口与数据结构（保留未来开分店能力）。
- 不改核销校验与 H5 交互。

## Decisions

### BD1 仅收敛种子数据，不删接口

- 备选 A：删除 POST /admin-api/stores 与多店结构 → 破坏面大，未来开分店需回滚代码。
- 备选 B：仅种子只留 1 家 + 前端收敛入口，接口契约原样保留。
- **取舍：选 B**。数据规模即业务事实，接口通用性无成本；契约不变（api.md 记录口径）。

### BD2 核销请求固定携带默认门店 id

核销表单不再展示下拉，提交时取列表首店（正隆记总号）id；后端门店匹配校验保留不动，天然兼容。

## Risks / Trade-offs

- [历史自提订单关联已删除门店导致核销记录门店名缺失] → 演示环境 H2 内存库重启即重置，无跨重启历史数据；生产接入前如保留多店历史需迁移脚本（当前不适用）。
