# design/backend.md — 提交上架生效

### BD-01 create 按请求 status 落库，非法值安全兜底

- 结论：`ProductService.create()` 中 `product.setStatus("OFF")` 改为按 `body.status()` 解析：仅 `"ON"` 映射为上架，其余（`"OFF"`、null、空白、任意非法字面值）一律落 `"OFF"`。
- 取舍：不做枚举异常抛出（创建接口对非法 status 静默降级为草稿），理由：草稿是安全态，抛异常反而让「误传脏数据」阻塞建档；与现有 `FC-075`（更新接口状态枚举校验抛错）不同——那条路径是显式上下架操作，需要明确反馈。
- 否决的替代方案：复用 `updateStatus()` 的枚举校验并在非法时抛「状态非法」——否决，理由同上，创建场景缺省即草稿更符合「保存草稿」按钮语义。

### BD-02 审计日志不变

- 新增商品审计仍记录「新增商品 商品[id] 名称」，不追加 status（上下架行为另有 `POST /admin-api/products/status` 审计，避免双份记录）。

### 风险取舍

- 兼容性风险：低。历史上仅有本仓库管理端调用该接口，且前端只传 `ON`/`OFF`；其他调用方（若有）传非法值将从「恒 OFF」变为「恒 OFF」（行为不变）。
