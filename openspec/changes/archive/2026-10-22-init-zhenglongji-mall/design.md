# Design: init-zhenglongji-mall

## 架构决策

| 决策 | 选择 | 理由 |
|---|---|---|
| 总体架构 | 前后端彻底分离：backend(8080) + frontend-h5(10086) + frontend-web(5173) | 复刻 qingguoji-mall 验证过的结构；后端不托管前端页面 |
| 后端 | Spring Boot 3.5 + JDK21 + Spring Data JPA + H2（生产 MySQL profile） | 免装库直接跑；若依风格分层 common/framework/mall |
| H5 端 | Vue3 + Vite + TS（不引入 Taro） | PRD 明确「仅 H5」，无小程序编译目标，去掉 Taro 降低复杂度 |
| Web 管理端 | Vue3 + Element Plus + Vite | 参考项目同栈 |
| 金额 | 全链路以「分」为单位整数存储与计算 | PRD 6.0 禁止浮点 |
| 库存 | 实物 = 可用 + 预占 + 冻结；乐观锁条件更新（version/可用量 CAS） | FR-11-1 / FR-11-5 / E-03 |
| 幂等 | 下单幂等键表（5 分钟窗口去重）；退款幂等 = 售后单号+退款序号 | FR-04-2 / FR-13-4 |
| 核销码 | 服务端按 orderNo + 分钟窗口哈希生成 6 位码，校验当前窗口±1，H5 每分钟自动刷新 | FR-04-8 防截图盗用 |
| 超时关单 | 定时任务 30s 扫描待支付超 15 分钟订单，关单前二次校验支付状态，释放预占 | FR-04-5 / FR-11-5 |
| 售后流转 | aftersale_flow 表只插不改不删，双端时间线同源 | FR-06-5 |
| 审计 | audit_log 表记录操作人/时间/IP/动作/变更前后值（上下架、改价、积分调整、资金操作） | FR-10-2 / 第十节 |
| 违禁词 | 内置功效宣传词库（提神/醒脑/保健/治疗…），商品保存与上架前校验，命中阻断 | FR-02-3 / 合规底线 |
| 模拟支付 | POST /api/orders/{no}/pay 即支付成功；保留回调+主动查询双通道语义（注释标注接入点） | RK-01 阻塞项未决 |

## 各方责任与对接点

- 后端：实现 api-contract 全部接口；金额/运费/积分抵扣一律服务端计算；所有状态变更服务端事件驱动。
- H5：只消费 /api/**；警示语与未成年人提示硬编码在详情页与结算页（不依赖后台配置）。
- Web：只消费 /admin-api/**；危险操作（上下架、退款、积分调整、盘点确认）二次确认。
- E2E：`tests/e2e/e2e-mall.mjs` 按 FR 编号逐条断言，产出测试报告数据。

## 契约疑问

无（本 change 即契约基线，由 api-contract delta 建立）。

## 已知 Gap

- ⚠️ 支付/短信为模拟通道（RK-01 槟榔类目报备未决），正式接入需新 change 替换通道实现。
- ⚠️ 对账任务为简化版（扫描模拟支付流水自校验 + 资损监控四类告警逻辑内置），接真实渠道后启用 T+1 账单文件解析。
- ⚠️ 导出为同步 CSV（FR-12-3 要求异步任务，数据量小阶段同步返回即可，接口语义保留）。
