# 前端设计（frontend）

## Context

- 上一 change（`2026-11-05-202611-需求基线-v1.8`，已归档）将需求资产以「`docs/需求/` 稳定基线库 + change `prd/` 输入快照」双层存放，并将主规格 H5-11 / WA-18 的结构基准指向 `docs/需求/*.html`。
- 现收敛为**PRD 单点存放**：只保留 PRD 一份，位于需求基线 change 的 `prd/` 目录；`docs/需求/` 整层删除（含 H5 原型、Web 管理端原型、时序图与流程图、需求总览 4 个配套件）。
- 删除原型 HTML **不造成规格断链**：PRD 附录 A「原型思路（线框描述）」本身已完整承载原型的结构基准内容 —— A.1 含 H5 商城端页面流程与「商品详情页 / 确认订单页 / 地址列表与编辑表单」关键页面线框，A.2 含 Web 管理端左侧导航 2 级信息架构与「商品新增编辑 / 售后工单详情 / 售后详情」页面线框。主规格改为引用 PRD 章节锚点即可覆盖同等信息量。

## Goals / Non-Goals

**Goals**

- PRD 单点存放，无重复副本、无文档同步负担。
- 主规格的结构基准引用与文件系统路径解耦：PRD 无论存放在哪、是否再次归档，规格均不失效。
- 结构基准的**信息量与语义不降级**：改引用后仍能定位到与原型等价的线框描述。

**Non-Goals**

- 不修改 PRD 正文任何字符。
- 不改动任何前端工程源码、依赖、构建配置。
- 不回改已归档 change 的历史快照；本次以独立 change 承接决策修订。

## Decisions

### FD1：PRD 单点存放于需求基线 change 的 `prd/` 目录

- **方案**：PRD 唯一存放点为 `openspec/changes/archive/2026-11-05-202611-需求基线-v1.8/prd/槟榔商城-PRD-v1.0.md`，删除 `docs/需求/` 整层。
- **理由**：遵循 change 内 `prd/` 目录规范（需求随 change 走）；消除 PRD 双副本带来的「改一处漏一处」同步负担。
- **取舍**：PRD 的仓库路径含归档日期前缀（`archive/2026-11-05-202611-需求基线-v1.8/`），若该 change 被二次改名或迁移，路径会变。因规格已改为章节锚点引用（FD2），此类变动不再波及主规格，仅需同步 `config.yaml` / `AGENTS.md` / `README.md` 三处路径声明。

### FD2：主规格结构基准改用 PRD 章节锚点引用

- **方案**：H5-11 改为「以 PRD v1.0 附录 A.1『H5 商城端页面流程与关键页面线框』为结构基准」；WA-18 改为「以 PRD v1.0 附录 A.2『Web 管理端信息架构』为结构基准」。**结构基准描述与全部场景逐字保留**。
- **理由**：
  - 规格引用「章节」而非「文件路径」，实现了解耦 —— PRD 的存放位置由 `config.yaml` 一处声明，规格不必重复承担路径维护成本。
  - PRD 附录 A 本就是原型的线框转述，引用附录 A 与引用原型 HTML 的信息量等价。
- **取舍**：附录 A 是线框描述（文本级），不如 HTML 原型可交互。后续若要恢复可视化原型对照，需另立 change 将原型重新入库，并在规格中并列引用。

### FD3：4 个配套交付件不入库

- **方案**：H5 原型 / Web 管理端原型 / 时序图与流程图 / 需求总览均不入库，随 PRD 一并留在仓库外的原始交付目录。
- **理由**：
  - PRD 8.4 章节内已**内嵌** 7 张 Mermaid 图源码（下单支付、支付确认时序、订单状态机、退款时序、核销时序、库存扣减链路、上下架流程），与时序图 HTML 内容重叠，缺失 HTML 不丢信息。
  - PRD 附录 A 已承载原型线框；需求总览为 PRD 的索引摘要，PRD 本身即其展开体。
- **取舍**：可视化原型不再随仓库分发，评审时需回原始交付目录查看。

## Risks / Trade-offs

- **[风险] PRD 路径变更需同步三处声明**：`config.yaml` / `AGENTS.md` / `README.md` 各自硬编码了 PRD 路径。
  → **缓解**：三处已同步为同一路径；后续 PRD 再迁移时须一并更新，并在 `config.yaml` 修订记录留痕。

- **[风险] PRD 附录 A 的线框描述与已实现页面可能漂移**：规格基准改为文本描述后，不再有可交互原型可供直观比对。
  → **缓解**：规格中已明确「页面数据 SHALL 来自真实接口，不得硬编码原型的示例数据」；H5-11 的两个场景（商品清单渲染、破图兜底）与 WA-18 的场景（新增商品三步流程）仍提供可执行判据。
